Accent-Based Regional Origin Identification

Case study

Pondicherry University

Developed a multiclass accent classification system by extracting and temporally aligning 7 speech features — MFCC, Mel-spectrogram, Spectral Contrast, Chroma, ZCR, RMS and Tonnetz — from 1,164 self-collected audio samples covering Kerala and Tamil Nadu English speech. Created a robust dataset and an evaluation pipeline for comparing multiple model architectures.

Benchmarked 5 architectures (SVM, Logistic Regression, ANN, 1D-CNN, 2D-CNN) with regularisation, data augmentation and class weighting. The optimised 4-block 2D-CNN over stacked spectrogram-like tensors achieved 97.4% test accuracy with a 0.99 ROC-AUC, evaluated on a held-out, stratified 20% split of unseen speakers — outperforming the SVM (90%) and ANN (93%) baselines.

Mineral Region Segmentation via Multispectral Remote Sensing

Case study

Pondicherry University

Engineered an end-to-end semantic segmentation pipeline for mineralisation mapping over Salem District (9,561 km², 5.79M valid pixels) using Landsat-8 satellite imagery (7 spectral bands, 30 m resolution). Applied PCA reduction (97.68% variance retained, 3 components) and up to 15-channel multi-source geospatial feature fusion across five tested input configurations.

Resolved a severe 2,509:1 class imbalance (2,309 labelled mineral pixels out of 5.79M) via a Weighted BCE (pos_weight=45) + Dice loss combination. Independently designed and comparatively trained three encoder-decoder architectures (U-Net, Attention U-Net, ResUNet) using the AdamW optimiser with early stopping on validation IoU. ResUNet-15ch was the most operationally effective model, achieving the highest mineral recall (92.42%) — critical for geological survey applications.

MediAssist — RBAC-Based Medical RAG Chatbot

Technical overview

Personal project

Built a role-based-access-control medical chatbot on a hybrid retrieval RAG pipeline indexing 88,195 chunks in Pinecone across 9 medical textbooks, embedded with PubMedBERT. Retrieval fuses full-corpus BM25 reranking with vector search using true Reciprocal Rank Fusion, and every retrieved chunk is filtered by the caller's role — Doctor, Nurse or Admin — before generation.

The Groq · Llama 3.3 70B generation step emits explicit REASONING and FINAL_ANSWER markers so clinicians can audit how an answer was reached, and a live LLM-as-judge scores every answer for faithfulness against retrieved context, triggering one capped regeneration on failure. Hardened through a full security & architecture audit — 14 revisions covering JWT refresh-token role re-verification, a path-traversal fix on the upload endpoint, secret rotation with git filter-repo, and a GitHub Actions CI/CD gate (lint → tests → Docker build → deploy).

VideoMind — Multimodal Video Question-Answering

Case study

Personal project

Built a multimodal video question-answering system that retrieves both what was said and what was shown. Videos are ingested via yt-dlp, audio is transcribed with faster-whisper / Groq ASR, and sampled frames are dual-indexed — transcript chunks into a 384-dim BGE text index, frames into a 512-dim CLIP ViT-B/32 visual index, both in Pinecone under one video_id.

Each query fuses both indexes at a tuned 0.6 text / 0.4 visual weighting, reranks by timestamp proximity, and a Groq LLM answers under a "cite only supplied evidence" prompt, linking back to the exact timestamp the answer came from. Hardened after real-load testing — a FastAPI lifespan hook pre-loads the embedding model to fix a cold-start race with Streamlit's status poller, a sliding-window rate limiter keeps requests under Groq's TPM budget, and swappable StorageBackend / LLMProvider abstractions make the deployment target config-driven, not hardcoded.

Message Notification Router

Case study

HackerRank Orchestrate — 24-hour hackathon

Built a personalized, multimodal triage system for WhatsApp messages in a 24-hour hackathon, deciding whether each message should notify, go to a digest, or be muted. Messages are normalised to plain text regardless of modality — EasyOCR for images, int8-quantized faster-whisper for voice notes — then matched against the recipient's quiet hours, engagement history and sender verification / opt-out status using sentence-transformer embedding retrieval.

A tiered decision pipeline resolves 46 of the 110 evaluation messages (42%) with conservative rules before touching a model, then routes the rest in batches of four through a Groq gpt-oss-120b → gpt-oss-20b → local Ollama (Llama 3.1 8B) fallback chain. A persisted per-model daily token-budget tracker switches tiers before a rate limit is hit, and every output is validated against a strict action / message_type contract with citation-ID verification against retrieval — a deterministic fallback guarantees a valid decision even if every model tier fails.

Industrial Intelligence Agent — AI Operations Copilot

Personal project

90%

Building an agentic decision-support system that investigates abnormal factory-machine behaviour and produces evidence-backed maintenance recommendations, instead of a chatbot that free-generates answers. A LangGraph agent plans which evidence a query needs and pulls it from three independent sources — PySpark-derived machine health metrics, historical PostgreSQL records, and a maintenance-document knowledge base — before Gemini (via Vertex AI) synthesises a root-cause analysis with explicit citations.

The RAG layer ships two retrieval backends behind one contract — a Pinecone + Vertex AI dense retriever for production, and a dependency-free BM25 lexical retriever that the system automatically degrades to if cloud credentials or connectivity are unavailable — so the agent never goes fully silent. Risk scoring, anomaly thresholds and all numeric evidence are computed deterministically in code; the LLM is only allowed to interpret and explain evidence it was actually given, never invent it.

Personal project · own real-money account

40%

Designing and building a deterministic, risk-controlled automated trading system for Indian index options (NIFTY / BANKNIFTY) on the Groww Trading API, for personal use on my own account rather than as a signal-selling or fund-management product. The pipeline chains market-regime detection, per-regime strategy selection, option-contract selection and a centralised risk engine before any order reaches the broker — deliberately keeping the entry/exit decision rule-based rather than model-driven, so every trade is auditable and reproducible.

Core safety mechanisms include automatic target/stop-loss/trailing-stop exits via broker-side OCO orders, a daily-loss kill switch, position reconciliation against the broker's actual state, and a paper/live trading-mode switch that defaults to disabled so no real order can be placed accidentally during development.

E-Commerce Customer Retention & Growth Analytics Platform

Personal project · Olist Brazilian e-commerce dataset

40%

An end-to-end analytics platform on ~100k real Olist orders, built to demonstrate the full data-scientist workflow rather than a single model. A PostgreSQL star schema (fact_orders with customer/product/seller/date dimensions) backs 15–20 business queries — RFM segmentation, cohort repeat-purchase rate, late-delivery-by-region — followed by proper hypothesis testing (t-tests, chi-square) on real relationships in the data, such as payment method vs. order value and delivery lateness vs. review score.

On top of that, a clearly-labelled simulated A/B test evaluates a retention-email intervention with random assignment, a power/sample-size justification, and a proportions test with confidence interval on the lift. The final layer trains an XGBoost churn-risk model and picks its classification threshold by cost/benefit — estimated retained revenue from targeting the highest-risk decile against the cost of the offer — rather than defaulting to 0.5, tied together in a Streamlit dashboard.
